# Forced Alignment with the Montreal Forced Aligner (MFA)

End-to-end forced alignment of the provided speech dataset using **Montreal Forced
Aligner 3.4.3**: data inspection, corpus preparation, validation, alignment,
boundary inspection and visualisation, plus two extra-credit experiments
(a custom G2P pronunciation dictionary and a second acoustic model).

Forced alignment takes audio plus the verbatim transcript of that audio and
works out *when* each word and each phoneme is spoken. The output is one
Praat **TextGrid** per audio file with a `words` tier and a `phones` tier.

## 1. Installation

MFA is installed **with conda**. A pip install does not work: MFA's PyPI wheel
does not install `kalpy`, the Kaldi Python bindings it imports at startup, and
`kalpy` has no PyPI distribution at all (it is conda-forge only). On Windows a
pip-installed MFA fails immediately with `ModuleNotFoundError: No module named
'_kalpy'`.

```bash
# 1. install Miniconda (skip if you already have conda)
#    Windows: https://repo.anaconda.com/miniconda/Miniconda3-latest-Windows-x86_64.exe
#    Linux/macOS:
#      curl -LO https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
#      bash Miniconda3-latest-Linux-x86_64.sh
```

```bash
# 2. create the environment (this repository ships environment.yml)
conda env create -f environment.yml
conda activate aligner

# or, equivalently, straight from conda-forge:
conda create -n aligner --override-channels -c conda-forge montreal-forced-aligner -y
conda activate aligner
```

```bash
# 3. verify
mfa version
# 3.4.3
```

The scripts in `scripts/` are plain Python and use the packages that MFA already
brings (`praatio`, `matplotlib`, `soundfile`, `numpy`), so the `aligner`
environment runs the whole pipeline. See `requirements.txt` for the exact
scripting dependencies.

### Download the models

```bash
mfa model download dictionary english_us_arpa
mfa model download acoustic   english_us_arpa
```

Both are required by `mfa align`: the **dictionary** maps words to phonemes, the
**acoustic model** maps phonemes to audio.

Models used in this report (see [`Report/versions.txt`](Report/versions.txt)):

## 2. The dataset

The dataset is the pre-selected set supplied with the assignment and lives in
this repository under `data/raw/` — nothing else was downloaded or substituted.

* `data/raw/wav/` — 6 audio files
* `data/raw/transcripts/` — 6 transcripts
* `data/raw/Assignment_2a.pdf` — the assignment brief

Verified properties (via `scripts/00_inspect_dataset.py`, results in
`data/dataset_summary.json`):

| Property | Finding |
|---|---|
| Files | 6 wav, 6 transcripts, **exact 1:1 stem match**, no orphans |
| Containers | **mixed**: 3 × NIST SPHERE (`BU_Radio_Corpus`, speaker `f2b`) and 3 × RIFF/WAVE |
| Sample rate | 16,000 Hz for all six |
| Channels | mono for all six |
| Sample width | 16-bit PCM for all six |
| Empty / missing transcripts | **0** |
| Total duration | 97.16 s (25.31 / 28.65 / 30.71 / 4.13 / 3.88 / 4.50 s) |

Two properties of the raw data needed handling:

1. **The `F2BJRLP*.wav` files are not WAV.** They are NIST SPHERE files
   (`NIST_1A` header) despite the `.wav` extension. MFA cannot read them, so the
   preparation script decodes the header and rewrites them as 16-bit PCM
   RIFF/WAVE using only the Python standard library — no `sox` or `ffmpeg`
   needed. Converted sample counts match the source headers exactly.
2. **Three transcripts use an upper-case `.TXT` extension.** MFA matches
   transcript to audio by *stem*, and `.TXT` is not found on a case-sensitive
   filesystem. The prep script looks transcripts up by lower-cased stem.

## 3. Prepare the dataset

MFA wants a **corpus directory** in which every `<name>.wav` sits next to a
`<name>.lab` containing the words spoken in that file. Build it with:

```bash
python scripts/00_inspect_dataset.py     # inspect only, writes data/dataset_summary.json
python scripts/01_prepare_corpus.py      # build data/corpus/ (wav + lab)
```

`01_prepare_corpus.py` is idempotent — it wipes and rebuilds `data/corpus`
every run, so the corpus always mirrors `data/raw`. It performs three
transformations:

* **container conversion** — NIST SPHERE → RIFF/WAVE; RIFF files are copied;
* **stem normalisation** — `<name>.lab` is written with exactly the wav stem;
* **text normalisation** — lower-cased, sentence punctuation removed, whitespace
  collapsed, hyphens and apostrophes kept.

Normalisation was checked against the dictionary rather than guessed. One
subtlety is worth calling out: `S.J.C.'s` must tokenise to `s j c 's`, not
`s j c s`. Both `s` and `'s` are dictionary entries, but they are different
sounds (`EH1 S` versus `Z` / `AH0 Z`), so dropping the apostrophe silently
mis-pronounces the word. The script preserves standalone clitics
(`'s`, `'ll`, `'re`, `'ve`, `'d`, `'m`, `'t`) for this reason.

Result: `data/corpus/` holds **6 wav + 6 lab** files, 0 failures.

## 4. Validate, then align

```bash
# check for problems first: OOV words, unreadable audio, empty transcripts
mfa validate data/corpus english_us_arpa --output_directory logs/mfa_validate

# forced alignment
mfa align data/corpus english_us_arpa english_us_arpa outputs --clean
```

or run the whole pipeline — inspect → prepare → validate → align → verify
counts — in one go:

```bash
./scripts/run_pipeline.sh
```

`mfa validate` on this corpus found **no** audio or transcription problems. It
did find 5 out-of-vocabulary word types, listed in
`logs/mfa_validate/oovs_found_english_us_arpa.txt`:

```
dukakis      (2 occurrences)
politicize   (1)
maffy        (1)
wbur         (1)
melnicove    (1)
```

`mfa align` produced **6 TextGrids for 6 wav files, 0 failures**, in 214 s
(`logs/align.log`). The verifier below is part of `scripts/03_align.sh`:

```bash
find data/corpus -name '*.wav' | wc -l        # 6
find outputs     -name '*.TextGrid' | wc -l   # 6
```

## 5. Inspect the alignment

```bash
python scripts/04_inspect_textgrids.py
```

For every TextGrid this prints the measurements quoted in the report and writes
a figure to `Report/figures/<name>_alignment.png` containing:

1. full waveform with word boundaries,
2. full waveform with phone boundaries,
3. zoomed waveform with the **word** tier labelled,
4. zoomed waveform with the **phone** tier labelled.

For the zoom of an OOV region specifically:

```bash
python scripts/04_inspect_textgrids.py --files F2BJRLP2 --zoom-start 4.5 --zoom-end 7.0 \
    --suffix _oov_zoom --stats-json logs/oov_zoom_stats.json
```

Praat is not required; the TextGrids are parsed with `praatio` and the waveform
is read with `soundfile`. If you do have Praat, the generated files open
directly (`outputs/F2BJRLP1.TextGrid`).

## 6. Extra credit

### 6a. Custom pronunciation dictionary from a G2P model

```bash
mfa model download g2p english_us_arpa

# pronunciations for every word in the transcripts (282 lines / 148 types)
mfa g2p data/corpus english_us_arpa dictionaries/g2p_all_words.dict

# pronunciations for only the words the base dictionary lacks (13 lines / 5 types)
mfa g2p data/corpus english_us_arpa dictionaries/g2p_oov_only.dict \
    --dictionary_path $MFA_ROOT/pretrained_models/dictionary/english_us_arpa.dict

# merge base dictionary + G2P entries -> dictionaries/english_us_arpa_plus_g2p.dict
python scripts/05_build_custom_dictionary.py \
    --base-dictionary $MFA_ROOT/pretrained_models/dictionary/english_us_arpa.dict

# re-validate and re-align
mfa validate data/corpus dictionaries/english_us_arpa_plus_g2p.dict \
    --ignore_acoustics --output_directory logs/validate_custom
mfa align data/corpus dictionaries/english_us_arpa_plus_g2p.dict english_us_arpa \
    outputs_custom_dict --clean

# compare the two runs
python scripts/06_compare_alignments.py
```

(`$MFA_ROOT` is where MFA keeps its models, by default `~/Documents/MFA`.)

Results:

* OOV words: **5 types → 0**. `logs/validate_custom/utterance_oovs.txt` is empty.
* `spn` (MFA's unknown-phone symbol) spans: **6 → 0**.
* Phone counts are unchanged for the four files with no OOV (372/13/12/13) and
  increased only in the two affected files (284→299, 328→345).
* Word boundaries moved by a mean of 12.9 ms (F2BJRLP1) and 2.8 ms (F2BJRLP2);
  the other four files are byte-identical. See
  `Report/alignment_comparison.json`.

### 6b. Second acoustic model

```bash
mfa model download acoustic   english_mfa
mfa model download dictionary english_mfa
mfa align data/corpus english_mfa english_mfa outputs_acoustic_english_mfa --clean
python scripts/06_compare_alignments.py --reference-dir outputs \
    --test-dir outputs_acoustic_english_mfa \
    --out-json Report/alignment_comparison_english_mfa.json
```

`english_mfa` uses the MFA/IPA phone set (72 distinct labels) instead of ARPA
(54 labels incl. stress digits), and its dictionary is missing
`judgeships`, which `english_us_arpa` knows — so it produced **7** `spn` spans
rather than 6. Word boundaries differ far more than for the dictionary swap:
a mean of 12–34 ms across **all six** files.

## 8. Reproducing from scratch

```bash
conda env create -f environment.yml
conda activate aligner
mfa model download dictionary english_us_arpa
mfa model download acoustic   english_us_arpa
./scripts/run_pipeline.sh
python scripts/04_inspect_textgrids.py
```

Re-running `run_pipeline.sh` overwrites `data/corpus/` and `outputs/`;
`--clean` is passed to `mfa align` so stale TextGrids are removed rather than
left behind.

## 9. Notes on MFA 3.4.3

Two MFA subcommands fail on this data and were worked around; both are recorded
in `logs/commands.log` because they were genuinely attempted:

* `mfa find_oovs` on the merged dictionary → `sqlalchemy.exc.IntegrityError:
  UNIQUE constraint failed: word.id`. `mfa validate --ignore_acoustics` reports
  the same OOV information and works.
* `mfa compare_alignments` → `TypeError: 'KeyError' object is not subscriptable`
  while loading a TextGrid-only directory. Replaced by
  `scripts/06_compare_alignments.py`.

Also worth knowing: this corpus is flat (no speaker subdirectories), so MFA
treats all six files as a single speaker named after the directory (`corpus`)
and applies fMLLR speaker adaptation across them. The six files in fact come
from two different sources — three BU Radio Corpus broadcast recordings and
three ISLE read sentences — which shows up in the quality metrics
(`outputs/alignment_analysis.csv`): speech log-likelihood is ≈ −46 for the BU
files but ≈ −61 for the ISLE files. Running with `--single_speaker` disables
that adaptation and is the first thing to try if quality matters.
